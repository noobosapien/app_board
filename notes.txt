From the vendor shown example https://github.com/WeActStudio/WeActStudio.EpaperModule/blob/master/Example/EpaperModuleTest_Arduino_ESP32/EpaperModuleTest_Arduino_ESP32.ino. 
The driver chip used is SSD1680.

The data sheet for that eink driver is https://www.e-paper-display.com/SSD1680%20Specificationffb0.pdf?method=picker&flag=all&id=ea90f3d3-ed7d-48b1-98f7-b82aaba50c93&fileId=960&v=1.zip

176 x 296 pixels, 1 pixel = 1 bit.
Has an embedded booster
Colors: R/B/W
There is an on chip RAM. Therefore the frame buffer can be sent straight using SPI.
5 programmable LUTs
Each LUT: 48 phases, 4 phases/group, which is 12 groups.
Embedded OTP to store waveform settings and parameters: 36 sets.
There are many pins in the die, but 8 exposed pins.
SPI + Busy + Res + D/C + Vcc + Gnd

Supports 3 or 4 wire SPI. This is most likely 4 wire SPI due to D/C line. There should be a connection between BS1 and Vss.

For a command SCL should be a rising edge. SDA is the bit. D/C should be low. C/S should be low.
For a data SCL should be a rising edge. SDA is the bit. D/C should be high. C/S should be low.

The order of recieving is D7, D6, D5, ..., D0.
For read operations send the command as usual and the line of SDA will have the read data from the controller from the next clock cycle.
VGH, VGL, VSH1, VSH2, VSL and VCOM needs an external circuit to power up poperly. This is probably already done in the board.

1 set of RAM 176 x 296 bits for Mono B/W
1 set of RAM 176 x 296 bits for Mono Red

3 Colors are used in this display so:
When the data bit in the Red RAM is 1 the color is always Red.
When Red is 1 and B/W is 0, LUT 2 is used to drive Red.
When Red is 1 and B/W is 1, LUT 3 is used to drive Red it is the same as LUT 2.

When Red is 0, B/W is 0 LUT 0 is used to drive the color Black.
When Red is 0, B/W is 1 LUT 1 is used to drive the color White.

For the programmable waveform of Source and VCOM, there are 12 groups with 4 phases each, with 2 state repeats.
In total there are 48 phases. In each phase the length can be set for a number (TP[nX]) 0 - 255.
Each group can be repeated with repeat counting number SR[nAB]/SR[nCD] from 1 to 256.
Each AB/CD phases can be repeated with state repeat counting numbers (SR[NAB]/SR[nCD]) from 1 to 256.
For the voltage, there are four levels for source voltage (VSS, VSH1, VSH2, VSL)
For VCOM there are 3 levels (DCVCOM, VSH1 + DCVCOM, VSL + DCVCOM)

TP[nX] is the phase length set by the number of frames n is the group number 0-11, X is the phase number A-D
when TP[nX] = 0, the phase is skipped. When TP[nX] = 1, the phase is 1 frame, and so on. Max 255 frames.

RP[n] is the repeat counting number for the group.
The range is from 0 to 255
n represents the group number 0 to 11
RP[n] = 0 indicates that the repeat times = 1, RP[n] = 1 indicates repeat time is 2. Max = 256 repeats.

SR[nAB] and SR[nCD] represent the state repeat counting number for phase A & B and phase C & D.
Range is 0 - 255
n is the group number from 0 to 11
SR[nXY] = 0 indicates the repeat times = 1, SR[nXY] = 1 indicates the repeat times = 2. Max is 256

VS[nX-LUTm] represents Source and VCOM voltage level which is used in each phase.
n represents the group number from 0 to 11.
m represents the LUT number from 0 to 4.

FR[n] represents the frame rate of group n.
The range of FR[n] is from 0 to 7.
n represents the group number from 0 to 11.

XON[nAB] and XON[nCD], indicates the gate scan selection.
n represents the group number from 0 to 11.
XON[nXY] = 0 indicates normal gate scan in Phase[nX] & Phase[nY]
XON[nXY] = 1 indicates all gate on, that gate keeps high until the phase for normal gate scan, in Phase[nX] & Phase[nY]

VS[nX-LUTm], TP[nX], RP[n], SR[nXY], FR[n] and XON[nXY] are used to define the driving waveform.

void GxEPD2_EPD::_reset()
{
  if (_rst >= 0)
  {
    if (_pulldown_rst_mode)
    {
      digitalWrite(_rst, LOW);
      pinMode(_rst, OUTPUT);
      digitalWrite(_rst, LOW);
      delay(_reset_duration);
      pinMode(_rst, INPUT_PULLUP);
      delay(_reset_duration > 10 ? _reset_duration : 10);
    }
    else
    {
      digitalWrite(_rst, HIGH); // NEEDED for Waveshare "clever" reset circuit, power controller before reset pulse, preset (less glitch for any analyzer)
      pinMode(_rst, OUTPUT);
      digitalWrite(_rst, HIGH); // NEEDED for Waveshare "clever" reset circuit, power controller before reset pulse, set (needed e.g. for RP2040)
      delay(10); // NEEDED for Waveshare "clever" reset circuit, at least delay(2);
      digitalWrite(_rst, LOW);
      delay(_reset_duration);
      digitalWrite(_rst, HIGH);
      delay(_reset_duration > 10 ? _reset_duration : 10);
    }
    _hibernating = false;
  }
}

void GxEPD2_EPD::_writeCommandDataPGM(const uint8_t* pCommandData, uint8_t datalen)
{
  _pSPIx->beginTransaction(_spi_settings);
  if (_dc >= 0) digitalWrite(_dc, LOW);
  if (_cs >= 0) digitalWrite(_cs, LOW);
  _pSPIx->transfer(pgm_read_byte(&*pCommandData++));
  if (_dc >= 0) digitalWrite(_dc, HIGH);
  for (uint8_t i = 0; i < datalen - 1; i++)  // sub the command
  {
    _pSPIx->transfer(pgm_read_byte(&*pCommandData++));
  }
  if (_cs >= 0) digitalWrite(_cs, HIGH);
  _pSPIx->endTransaction();
}

Procedure:
If DC and CS are valid make them LOW.
Transfer from SPI the first byte and increment the address.
If DC is valid make it HIGH for data transfer.
For all the data in length, transfer the bytes.
Make chip select HIGH so it is not used anymore.

The way it is designed, the first byte is always the command.

void GxEPD2_EPD::_waitWhileBusy(const char* comment, uint16_t busy_time)
{
  if (_busy >= 0)
  {
    delay(1); // add some margin to become active
    unsigned long start = micros();
    while (1)
    {
      if (digitalRead(_busy) != _busy_level) break;
      if (_busy_callback) _busy_callback(_busy_callback_parameter);
      else delay(1);
      if (digitalRead(_busy) != _busy_level) break;
      if (micros() - start > _busy_timeout)
      {
        Serial.println("Busy Timeout!");
        break;
      }
#if defined(ESP8266) || defined(ESP32)
      yield(); // avoid wdt
#endif
    }
    if (comment)
    {
#if !defined(DISABLE_DIAGNOSTIC_OUTPUT)
      if (_diag_enabled)
      {
        unsigned long elapsed = micros() - start;
        Serial.print(comment);
        Serial.print(" : ");
        Serial.println(elapsed);
      }
#endif
    }
    (void) start;
  }
  else delay(busy_time);
}

void Adafruit_GFX::drawChar(int16_t x, int16_t y, unsigned char c, uint16_t color, 
uint16_t bg, uint8_t size_x, uint8_t size_y)
{

  if (!gfxFont) { // 'Classic' built-in font

    if ((x >= _width) ||              // Clip right
        (y >= _height) ||             // Clip bottom
        ((x + 6 * size_x - 1) < 0) || // Clip left
        ((y + 8 * size_y - 1) < 0))   // Clip top
      return;

    if (!_cp437 && (c >= 176))
      c++; // Handle 'classic' charset behavior

    startWrite();
    for (int8_t i = 0; i < 5; i++) { // Char bitmap = 5 columns
      uint8_t line = pgm_read_byte(&font[c * 5 + i]);
      for (int8_t j = 0; j < 8; j++, line >>= 1) {
        if (line & 1) {
          if (size_x == 1 && size_y == 1)
            writePixel(x + i, y + j, color);
          else
            writeFillRect(x + i * size_x, y + j * size_y, size_x, size_y,
                          color);
        } else if (bg != color) {
          if (size_x == 1 && size_y == 1)
            writePixel(x + i, y + j, bg);
          else
            writeFillRect(x + i * size_x, y + j * size_y, size_x, size_y, bg);
        }
      }
    }
    if (bg != color) { // If opaque, draw vertical line for last column
      if (size_x == 1 && size_y == 1)
        writeFastVLine(x + 5, y, 8, bg);
      else
        writeFillRect(x + 5 * size_x, y, size_x, 8 * size_y, bg);
    }
    endWrite();

  } else { // Custom font

    // Character is assumed previously filtered by write() to eliminate
    // newlines, returns, non-printable characters, etc.  Calling
    // drawChar() directly with 'bad' characters of font may cause mayhem!

    c -= (uint8_t)pgm_read_byte(&gfxFont->first);
    GFXglyph *glyph = pgm_read_glyph_ptr(gfxFont, c);
    uint8_t *bitmap = pgm_read_bitmap_ptr(gfxFont);

    // THIS IS ON PURPOSE AND BY DESIGN.  The background color feature
    // has typically been used with the 'classic' font to overwrite old
    // screen contents with new data.  This ONLY works because the
    // characters are a uniform size; it's not a sensible thing to do with
    // proportionally-spaced fonts with glyphs of varying sizes (and that
    // may overlap).  To replace previously-drawn text when using a custom
    // font, use the getTextBounds() function to determine the smallest
    // rectangle encompassing a string, erase the area with fillRect(),
    // then draw new text.  This WILL infortunately 'blink' the text, but

    startWrite();
    for (yy = 0; yy < h; yy++) {
      for (xx = 0; xx < w; xx++) {

        }
        if (bits & 0x80) {

          } else {
            writeFillRect(x + (xo16 + xx) * size_x, y + (yo16 + yy) * size_y,
                          size_x, size_y, color);
          }
        }
        bits <<= 1;
      }
    }
    endWrite();

} // End classic vs custom font

For the font, default Arduino font is better, due to how the bits are structured.
Each character will have 5 bytes, and they are ordered perfectly for ACII.
Each character is a bitfield of 8x5.

for (int8_t i = 0; i < 5; i++) { 
  uint8_t line = font[c * 5 + i];

  for (int8_t j = 0; j < 8; j++, line >>= 1) {
    if (line & 1) {
      if (size_x == 1 && size_y == 1)
        draw_pixel(x + i, y + j, color, frame_buffer);
    } else {
      if (size_x == 1 && size_y == 1)
        draw_pixel(x + i, y + j, color ^ 0xff, frame_buffer);
    }
  }
}

By shifting each bit to the right and getting the last bit will show the pixels of the character.
Only size of 1 is used, so checking for size doesn't matter here.

Note: when showing the buffers on display, always red should go first as empty bits of a character
will be black but the empty space should be white and it should be done after the red
using the B/W framebuffer.

color ^ 0xff should be used for empty spaces as the B/W should show 0x00 as the char color and 0xff
for the white spaces.
Red is the opposite, showing 0xff, which is desired, will glow red and empty spaces 0x00 will be black.
